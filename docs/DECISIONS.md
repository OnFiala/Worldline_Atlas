# Reference-export decisions

- Keep plain JavaScript, WebGL and a small Node/SQLite adapter. No new framework, service or dependency is required for the demonstration.
- Start a new public history. Private data, operational identities and old Git objects are not export material.
- Use a procedural grid and fictional examples. These make the implementation understandable without redistributing unresolved third-party images or datasets.
- Keep provider adapter code as disconnected examples with mocked tests. No automatic fetch, personal scheduler or hosting workflow is installed.
- Require explicit trusted writer authorization in the reusable API; expose only read routes in the loopback demo.
- Keep the voice-directed story factual and bounded. No complete voice-only audit or third-party endorsement is claimed.

The export can be changed independently of the private prototype. Reconsider the local architecture only when an actual shared deployment, authenticated writer or durable research workflow is separately specified. Adding those boundaries is outside this release.
